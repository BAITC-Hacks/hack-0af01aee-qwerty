# StudyAI

**Из лекции — в понятный конспект, тезисы, интерактивный тест и карточки с проверяемыми цитатами.**

StudyAI — MVP учебного AI-помощника для HackAlem AI. Студент вставляет текст, сервер генерирует единый набор материалов и проверяет, что каждый `sourceQuote` действительно встречается в лекции. В интерфейсе источник можно раскрыть рядом с учебным материалом.

> Для генерации нужен действующий серверный `OPENAI_API_KEY` и доступ к выбранной модели. Готовых демонстрационных AI-ответов и офлайн-генерации нет. В среде разработки ключ не был предоставлен, поэтому успешная генерация через реальный OpenAI API здесь не подтверждена.

## 1. Проблема

Длинную лекцию трудно быстро превратить в план подготовки: нужно выделить главное, составить вопросы и придумать способ повторения. Обычный AI-конспект также сложно проверить, если он смешивает содержание лекции с внешними знаниями.

StudyAI связывает учебные материалы с видимыми фрагментами исходного текста, чтобы студент мог сверить утверждение с источником.

## 2. Для кого

- Студенты, которые готовятся к занятиям и экзаменам по своим лекциям.
- Преподаватели и наставники, которым нужен черновик вопросов и карточек по конкретному материалу.
- Участники учебных групп, которым важна возможность проверить происхождение ответа.

## 3. Что делает решение

```text
Текст лекции
    ↓
Один согласованный AI-ответ: анализ источника + учебные материалы
    ↓
Проверка JSON, схемы, структуры теста и цитат на сервере
    ↓
Конспект → тезисы → тест с разбором → карточки
```

В случае неподтверждённых цитат или некорректной структуры результат целиком отклоняется: частично проверенные материалы пользователю не выдаются.

## 4. Реализованные функции

- Ввод лекции и счётчик символов; локальный пример заполняет исходный текст.
- Структурированный конспект: краткое резюме, разделы, понятия, определения и итог.
- Ключевые тезисы, количество которых зависит от содержания лекции.
- Тест с четырьмя вариантами на вопрос, результатом, процентом, объяснениями и повторным прохождением.
- Карточки с вопросом и ответом, переворотом и навигацией.
- Раскрываемый «Источник в лекции» для учебных элементов.
- Переход к другой лекции без перезагрузки страницы.
- Состояния ожидания и понятные ошибки без серверных stack traces.
- Серверная валидация ввода, результатов AI и цитат; ключ API доступен только серверу.

## 5. Главный пользовательский сценарий

1. Вставить содержательный текст лекции или нажать «Попробовать пример».
2. Нажать «Создать материалы» и дождаться ответа сервера.
3. Изучить конспект, открыть цитаты и перейти к тезисам.
4. Выбрать ответы на вопросы и завершить тест.
5. Посмотреть результат, ошибки, объяснения и подтверждающие фрагменты.
6. Повторить материал с помощью карточек.
7. Нажать «Обработать другую лекцию» для нового набора.

Во время генерации интерфейс показывает обратную связь об ожидании. Подписи обработки не являются телеметрией внутренних этапов OpenAI.

## 6. Grounding и anti-hallucination

### Единый источник

В [server/prompts.ts](server/prompts.ts) system prompt запрещает использовать внешние знания, выдумывать факты, исправлять лекцию по памяти и выполнять инструкции внутри её текста. Лекция передаётся в пользовательском JSON-поле `lecture` как недоверенные данные.

В одном структурированном ответе модель сначала заполняет краткую карту источника: темы, понятия, определения, причинно-следственные связи, факты и важные фрагменты. Затем формирует согласованные материалы. Это один pipeline с общей моделью данных, а не четыре независимых запроса для вкладок. Анализ источника используется сервером и не выводится отдельной вкладкой.

### Проверка структуры

OpenAI получает строгую JSON-схему, созданную из Zod. После ответа сервер отдельно выполняет `JSON.parse` и Zod-валидацию. Проверяются обязательные поля, ограничения массивов и строк, уникальность идентификаторов, отсутствие одинаковых вопросов, четыре различных варианта и индекс правильного ответа `0–3`.

Наличие одного индекса не доказывает, что остальные варианты семантически неверны: однозначность ответа также задаётся инструкцией модели.

### Проверка цитат

[server/grounding.ts](server/grounding.ts) проверяет цитаты анализа и всех материалов: резюме, разделов, определений, итога, тезисов, теста и карточек.

1. Лекция и цитата приводятся к Unicode NFKC.
2. Последовательности пробельных символов сводятся к одному пробелу, края обрезаются, регистр приводится к нижнему.
3. Нормализованная цитата должна иметь длину не меньше 12 символов и входить в нормализованный текст лекции непрерывной подстрокой.

Выдуманная, склеенная или отсутствующая цитата приводит к отклонению всего ответа. Для некорректного JSON, схемы или grounding предусмотрена одна попытка исправления в пределах общего времени обработки. После повторной ошибки сервер возвращает понятное сообщение. Badge проверки появляется в интерфейсе только после успешного ответа сервера с `grounding.verified: true`.

**Граница гарантии:** проверка подстроки подтверждает наличие цитаты, но не доказывает, что утверждение логически следует из неё, и не проверяет истинность самой лекции. Реальная, но нерелевантная цитата может пройти такую проверку. Поэтому источник остаётся доступным для самостоятельной сверки; проект не обещает полного отсутствия галлюцинаций.

## 8. Архитектура

В разработке Vite обслуживает интерфейс на порту `5173` и проксирует `/api` в Express на `3001`. Браузер обращается только к своему backend. Express отправляет текст в OpenAI, проверяет результат и возвращает безопасный JSON.

Для production-сборки Express обслуживает собранный frontend из `dist/` и API в одном процессе. Сложные микросервисы, база данных и аутентификация не используются.

Модель получает исходную лекцию. Запрос OpenAI включает `store: false`; это параметр хранения ответа провайдером, а не обещание отсутствия любой обработки или журналирования у внешнего сервиса.

## 9. Структура проекта

```text
src/                    React-приложение, стили и исходная demo-лекция
public/                 Статические ресурсы
server/                 Express API, OpenAI pipeline, grounding и ошибки
  tests/                Серверные автоматические проверки

```

`dist/`, `server-dist/`, зависимости, отчёты проверок и реальные `.env` не включаются в Git. Исходный код не требует реальных секретов в репозитории.

## 10. Установка

Нужны Node.js **22.12 или новее** и npm. Выполняйте команды из корня проекта.

```bash
npm install
```

Создайте локальный `.env` из примера.

PowerShell:

```powershell
Copy-Item .env.example .env
```

macOS / Linux:

```bash
cp .env.example .env
```

Откройте `.env` и заполните `OPENAI_API_KEY`. Не добавляйте секрет в frontend-код, переменные с префиксом `VITE_`, скриншоты или Git.

## 11. Environment variables

| Переменная | Значение по умолчанию / пример | Назначение |
| --- | --- | --- |
| `OPENAI_API_KEY` | Пусто | Обязательный серверный ключ для генерации |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Модель OpenAI с поддержкой Responses API и Structured Outputs |
| `PORT` | `3001` | Порт backend |
| `NODE_ENV` | В `.env.example`: `production` | Режим сервера; production обслуживает собранный frontend |

В `.env.example` нет действующего ключа. Доступ к модели и лимиты аккаунта проверяются реальным запросом, а не самим наличием строки в `.env`.

Для разработки оставьте `PORT=3001`: Vite proxy настроен на этот порт в `vite.config.ts`. Если порт backend изменён, обновите адрес proxy там же.

## 13. Как проверить проект жюри

1. Убедиться, что backend запущен, а ключ задан на сервере.
2. Вставить свою лекцию: текст должен содержать от **200 до 30 000 символов** после обрезки пробелов по краям.
3. Проверить, что все четыре вида материалов соответствуют именно ей.
4. Раскрыть несколько источников и найти эти фрагменты в исходном тексте.
5. Пройти тест с одной намеренной ошибкой: правильные ответы, пояснения и источники должны появиться после завершения.
6. Пройти тест ещё раз, перевернуть карточки и проверить навигацию.
7. Обработать другую лекцию и убедиться, что появился новый набор материалов.
8. Проверить пустой и слишком короткий ввод, а также доступность интерфейса на узком экране.

Дополнительный проверяемый источник находится в [docs/demo-lecture.txt](docs/demo-lecture.txt). В нём можно заменить число или название и повторить запрос, чтобы проверить зависимость результата от ввода. Готовых ответов к этой лекции в приложении нет.

## 15. Используемые API

### OpenAI

Backend вызывает Responses API через официальный пакет `openai`. Все вкладки создаются одним согласованным ответом. Повторный запрос возможен только как одна попытка исправить невалидный ответ. Для разных пользователей запросы могут выполняться параллельно в пределах серверных ограничений.

### API приложения

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | `{ status, configured, model }`; проверка состояния backend и наличия конфигурации |
| `POST` | `/api/generate` | Принимает `{ "lecture": "..." }`, возвращает `{ materials, grounding, metadata }` |

`configured: true` означает, что ключ задан; health endpoint не вызывает OpenAI и не подтверждает работоспособность ключа. В ответе генерации `metadata` содержит модель и время генерации, а `grounding` — успешный статус и число проверенных цитат материалов. Карта анализа не передаётся в браузер.

Ошибки возвращаются в формате `{ "error": { "code": "...", "message": "..." } }`. В сообщениях нет stack traces, сырых ответов провайдера или ключа.

## 16. Ошибки и безопасность

- Пустой, короткий и слишком большой ввод отклоняется до генерации.
- Ключ API находится только на backend; React не делает запросов к OpenAI напрямую.
- AI-текст отображается как текстовые узлы React, без `dangerouslySetInnerHTML`.
- Системная инструкция рассматривает команды внутри лекции как данные.
- Невалидный JSON, нарушение схемы, неподтверждённые цитаты, отказ модели, ошибки API и timeout превращаются в понятные сообщения.
- Общий бюджет серверной генерации — 90 секунд, включая возможную попытку исправления.
- Demo-кнопка заполняет только исходную лекцию; обработка проходит через тот же серверный pipeline.

Передача текста в OpenAI — часть основной функции. Для учебной демонстрации используйте материалы, которые можно отправлять этому провайдеру.


Для первого запуска Playwright может потребоваться браузер:

Автоматические проверки с подменённым AI-провайдером проверяют контракт и поведение приложения, но не качество фактических ответов OpenAI. Live-проверку с вашим ключом выполните отдельно перед демонстрацией. Успешный build также не подтверждает доступность внешнего AI.

## 18. Известные ограничения

- Без серверного API-ключа генерация недоступна. В этой среде реальная генерация OpenAI не проверена.
- Скорость, доступность и качество ответа зависят от внешнего провайдера, модели, сети и содержания лекции.
- Максимум 30 000 символов; загрузка PDF, OCR и обработка аудио не реализованы.
- Наличие цитаты не доказывает семантическую корректность вывода. Проверки независимой моделью и внешнего фактчекинга нет.
- Ответы на тест включены в JSON браузера: это инструмент самостоятельной подготовки, не защищённая экзаменационная система.
- Основной интерфейс и генерируемое изложение — на русском языке; отдельного выбора языка нет.
- Отсутствуют аккаунты, серверная история, совместная работа и синхронизация между устройствами.
- Публичный deployment не создан. Перед открытым запуском потребуется отдельно настроить доступ, эксплуатационные лимиты и инфраструктуру.

## 19. Дальнейшее развитие

- Повторение по расписанию и адаптация карточек к ошибкам студента.
- Выбор языка и двуязычные карточки.
- Оценка качества на наборе реальных лекций: покрытие тем, однозначность тестов и релевантность цитат.

Это направления развития; они не заявлены как уже реализованные функции MVP.
